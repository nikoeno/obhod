# Implementation plan — pc (internal/pc)

Status: everything under `internal/pc` is `planned` (M0 skeleton: `doc.go` + `API.md`; `Main` answers `--version` / `--help` only). Each module's `API.md` is the source of truth; this file only orders the work, lists the gaps found while reading the contracts, and proposes how to close them. Delete it (or fold the leftovers into a `DESIGN.md`) when `internal/pc` reaches `implemented`.

## 1. Milestones

One milestone per task (root `AGENTS.md`, Workflow 1). Each ends with `go vet ./...`, `go test ./...`, `go test -tags lab ./...` and `make cross` passing, plus a status update in the module's `API.md` header and in `docs/architecture.md`.

Dependency order:

```
M1 singbox ─────────────────────────────┐
M2 clashapi ─┬─ M7 monitor ─────────────┤
             └─ M8 status ──────────────┤
M3 procman ─────────────────────────────┼─ M9 pc config/CLI ── M10 pc App ─┬─ M11 smoke
M4 winws ─┬─ M6 desync ─────────────────┤                                  └─ M12 control API (UI)
M5 nfqws ─┘                             ┘
```

M1–M5 can start at once and in any order. M6 needs M4 + M5; M7 and M8 need M2. M12 needs M10. Suggested sequence for one person: M1 … M11, then M12.

The desktop UI is a separate Tauri app that talks to `splitter` over a local control API (`docs/adr/0003-desktop-ui-and-packaging.md`). M10 builds the connect/disconnect lifecycle the UI needs; M12 adds the API on top of it.

### M1 — `singbox` (pure generator)

Files: `singbox.go` (Config, Generate), `check.go` (Check, Command), `singbox_test.go`, `testdata/*.golden.json`, `check_integration_test.go` (`//go:build integration`).

- Build the config as Go structs (or ordered maps) and marshal it once. Sort every list (domains, process names) so equal input gives byte-identical output.
- Inbound: TUN (`auto_route`, `strict_route`, `stack`, address from `TUNConfig`). Sniffing is enabled so domain rules see SNI/Host.
- DNS: DoH servers from `DNSConfig`, plus a FakeIP range. The direct/desync domains resolve via the direct path; everything else follows the routing.
- Outbounds: `direct`, `desync` (a second direct outbound, so connections show their route; G5), `tunnel` (raw JSON from `Outbounds.Tunnel`, tag forced to `tunnel`), `proxy` (only if `Outbounds.Proxy` is set), and reject for `block`.
- Rule order exactly as in the contract: own processes → direct; QUIC (udp/443) reject when `BlockQUIC`; block; proxy; tunnel; desync → `desync`; direct → `direct`; `final` → default.
- Clash API: `ClashAPI` listen address + `ClashSecret` (generated by the app, G7). Validate that the listen address is loopback.
- Errors: empty `Outbounds.Tunnel`; a table entry routed `proxy` with no proxy outbound; an invalid table.
- `Check`: runs `<binary> check -c <file>` through `exec.CommandContext` and returns stderr wrapped in the error. `Command` is pure.

Tests: goldens for an empty table, a mixed table (all five routes), proxy set vs unset, and `BlockQUIC` on/off. Determinism: shuffle the input entries and compare bytes. Error cases. Integration: generate every golden and run the pinned `sing-box check` (skip when the binary is missing).

Verify against the pinned version: rule-action syntax (`action: reject` / `sniff` vs the legacy inbound `sniff`), the DNS server format (changed in 1.12), and `process_name` vs `process_path` on Windows.

### M2 — `lib/clashapi`

Files: `clashapi.go` (types, `New`), `client.go` (HTTP), `fake.go` (`NewFake`), `clashapi_test.go`, `testdata/connections*.json`, `testdata/version.json`.

- `GET /connections` → `Snapshot`; `GET /version` → string. Header `Authorization: Bearer <secret>`, sent only when the secret is non-empty.
- Decode into private wire structs, then map to the public types (`metadata.host`, `metadata.destinationIP`, `metadata.processPath`, `chains`, `rule`, `start` RFC 3339).
- Errors wrap the endpoint and the HTTP status: `clashapi: GET /connections: 401`. The secret never appears in an error or a log.
- Every request takes the caller's ctx. The default `http.Client` has a short timeout and **no proxy** (`Transport.Proxy = nil`), so a system proxy cannot capture localhost traffic.
- `NewFake`: returns snapshots in order, then repeats the last one. Safe for concurrent use.

Tests: `httptest` server replaying recorded fixtures (record from the pinned sing-box), checks for the auth header and a missing/empty secret, a 401/500 mapping, a malformed body, ctx cancel, and that fake ordering repeats the last snapshot.

### M3 — `procman`

Files: `procman.go` (types incl. `RestartPolicy` (G2), Manager, Start/Stop/Restart/StopAll), `supervise.go` (wait loop, restart backoff, events), `ring.go` (log ring buffer), `attr_windows.go` (Job Object via `kernel32.dll`, G3), `attr_linux.go` (Pdeathsig + process group, started from a thread-locked goroutine, G4), `attr_other.go` (`ErrUnsupported` or plain start), `procman_test.go`, `helper_test.go`.

- Start: `exec.Cmd` with the OS attributes, stdout/stderr → ring buffer of `LogLines` lines (+ the app log). Then call `Ready` (if set) with the caller's ctx; if `Ready` fails, stop the process and return the error.
- Supervision: one goroutine per process waits on `cmd.Wait`. Under `on-failure`, it restarts with exponential backoff from the `clock` and gives up (`State=failed`) after `MaxRestarts` within `RestartWindow`. Each transition emits an `Event` (buffered channel; drop the oldest rather than block).
- Process names for `CleanupStale` and status: `sing-box`, `winws2`, `nfqws2`.
- Stop: graceful first (Linux: SIGTERM to the process group; Windows: no console signals → go straight to `TerminateProcess` / job close), then kill after `StopTimeout`. `StopAll` stops in reverse start order.
- `CleanupStale`: `proc.Find` by name, filtered to processes whose path lives under our binary directory, then killed. Never kill a same-named process from elsewhere (for example another person's zapret install).
- `ErrNeedsAdmin`: map the OS error at start (Windows `ERROR_ELEVATION_REQUIRED` / access denied; Linux `EPERM`). Do not parse child output (contract).

Tests: re-exec the test binary as the helper (`TestHelperProcess` pattern, modes sleeper / crasher / slow-stopper / ready-after-N), so nothing has to be built. Cover ordering, readiness timeout, the restart-backoff schedule on the fake clock, giving up after `MaxRestarts`, the stop timeout → kill, `StopAll` order, the ring-buffer size, and `CleanupStale` with `proc.NewFake`. A subprocess test checks kill-on-parent-exit (start a parent helper that starts a child, kill the parent, assert the child is gone).

### M4 — `desync/winws` (pure, renders winws2 from zapret2)

Files: `winws.go`, `filter.go` (WinDivert filter builder), `winws_test.go`, `testdata/*.golden`.

- Hostlist: sorted, deduped, one domain per line, `\n` endings. Args reference it as `hostlist.txt` (resolved relative to the process `Dir`).
- Filter: `outbound and tcp and (tcp.DstPort == 443 or …) and ifIdx == N and not (ip.DstAddr in excludes / ipv6.DstAddr …) and not (tcp.SrcPort >= a and tcp.SrcPort <= b …)`. Build it from small helpers so each clause can be unit-tested.
- Validation: at least one domain, `IfIndex > 0`, valid prefixes, `from <= to` for every port range.
- zapret2 order: `--wf-tcp-out=<Ports>`, `--wf-raw-filter=<filter>` (ANDed with the rest by winws2), `--lua-init=@<LuaDir>/zapret-lib.lua`, `--lua-init=@<LuaDir>/zapret-antidpi.lua`, `--hostlist=hostlist.txt`, then the Lua strategy args verbatim (`--filter-l7`, `--payload`, `--out-range`, `--lua-desync=...`).

Tests: filter-clause units (IPv4, IPv6, mixed prefixes, port ranges), golden args + hostlist, determinism, invalid inputs. Integration (`//go:build integration`, Windows): `winws2.exe --help` from `third_party/bin` lists every flag we emit.

### M5 — `desync/nfqws` (pure, renders nfqws2 from zapret2)

Files: `nfqws.go`, `nft.go`, `nfqws_test.go`, `testdata/*.golden`.

- Args: `--qnum`, `--lua-init=@<LuaDir>/...` per `LuaInit`, `--hostlist`, then the Lua strategy args. `Mark` defaults to zapret2's own `0x40000000`.
- nft rules in their own `inet splitter` table, shaped like the zapret2 README example: a `postrouting` chain (priority 101) matching `oifname`, TCP dport in `Ports`, daddr not in exclude sets, sport not in exclude ranges, `meta mark & Mark == 0`, `ct original packets 1-12` → `queue num N bypass`; an `output` chain (priority -401) with `notrack` for marked packets. No reply queuing and no sysctl (out of scope). `NFTDown` = `nft delete table inet splitter`.
- Validation: domains present, `Uplink` non-empty and safe as an nft string (no quotes/whitespace), `Mark != 0`, `QueueNum` default 200.

Tests: golden args + rule list, IPv6-only and IPv4-only excludes, the down command never touches other tables, input validation. The real packet test belongs to the lab (Level 3), not here.

### M6 — `desync`

Files: `desync.go` (incl. `PortRange`, G1), `desync_test.go`.

- `Engine` default from `runtime.GOOS` (windows → winws, linux → nfqws, others → `ErrUnsupported`).
- `ExcludeIPs` empty → `ErrNoExcludeIP` (always checked first, even for an empty hostlist).
- `t.Domains(route.Desync)` empty → `Plan{Engine: e}` with no `Path`/`Args`/`Files`; the app treats that as "do not run".
- Refuse a virtual uplink (`uplink.Virtual`) — this enforces "never touch the TUN".
- Delegate: winws with `IfIndex = uplink.Index`; nfqws with `Uplink = uplink.Name`, and `Setup`/`Teardown` from `NFTSetup`/`NFTDown`. `Files["hostlist.txt"] = Hostlist`.

Tests: per-engine delegation (inspect the child outputs inside the plan), empty desync list, missing exclude, virtual uplink rejected, unsupported engine/OS. Use an explicit `Engine` in tests so they pass on any host OS.

### M7 — `monitor`

Files: `monitor.go` (New, Run, Stats), `detect.go` (pure heuristics over two snapshots), `monitor_test.go`, `testdata/*.json` (recorded snapshot sequences).

- Poll every `PollInterval` (clock-driven). Keep `map[id]conn` from the previous snapshot: ids that disappeared = closed; per-id byte deltas feed `Stats`.
- Heuristics (pure functions, one per verdict) as in the contract; each fires at most once per connection id. They map to `analyzer.Verdict` values that exist (`TLS_RST`, `STALL_16_20`, `TCP_TIMEOUT`); confirm the exact constants.
- `sink` is called outside the lock. API errors → backoff (clock), `Run` returns only on ctx cancel.
- Privacy: logs show the domain only at debug level; `Stats` are per route only.

Tests: one fixture sequence per heuristic, plus no false positive on a long normal download, a short normal request, or a UDP flow. Stats accounting across polls, recovery after API errors, ctx cancel.

### M8 — `status`

Files: `status.go` (Config, New, Run), `handlers.go`, `assets/index.html` (+ css/js, `//go:embed`), `status_test.go`, `testdata/status.golden.json`.

- `New` validates `Listen`: it must parse as a host:port whose host is a loopback IP (or `localhost`, resolved to loopback). Otherwise it returns an error.
- Handlers: `GET /` (embedded HTML), `GET /api/status` (JSON `Snapshot`), `GET /api/traffic` (from `live.Connections`, totals only, no per-connection hosts). Any other method → 405.
- Token: when set, require `?token=` and compare with `subtle.ConstantTimeCompare`.
- Hardening: check the `Host` header against the listen address (DNS-rebinding guard), `Content-Security-Policy: default-src 'self'`, `X-Content-Type-Options: nosniff`, and no CORS headers.
- `Run`: `http.Server` with timeouts, shut down on ctx cancel.

Tests: loopback validation (v4, v6, `0.0.0.0`, a LAN IP, a hostname), golden JSON from a fake `Source`, token required/accepted, a wrong Host header rejected, 405 on POST, assets served without external URLs (grep the embedded files for `http`).

### M9 — `pc` root: config + CLI

Files: `config.go` (Config, LogConfig, LoadConfig, defaults, validation), `cli.go` (subcommands), `main.go` (update), `config_test.go`, `testdata/*.yaml`, `testdata/*.golden`.

- `LoadConfig`: `yaml.v3` with `KnownFields(true)`; durations as strings; apply child defaults; validate (for example, the checker's `UnknownDefault` must match the sing-box final route — see G6).
- Clash API secret: 32 random bytes (`crypto/rand`, hex) generated at each start; never in config, never logged (G7).
- Secrets: read the tunnel outbound (JSON) and the optional proxy outbound from `Paths.Secrets/<file>` named in config. Never log them.
- CLI: `splitter run [--config path]`, `splitter check-config [--config path]` (loads config + secrets, renders sing-box + desync once into a temp dir, and runs `sing-box check` when the binary exists), `--version`, `--help`. Exit codes 0/1/2/3 as in the contract.
- Default config path: `<Paths.Config>/app.yaml`, from `paths.Default("splitter")` unless `paths.root` overrides it.

Tests: golden config loading (minimal, full, unknown key → error, bad duration, missing secret file), CLI exit codes, and `check-config` with a fake sing-box (a re-exec helper).

### M10 — `pc` root: App wiring and lifecycle

Files: `app.go` (New, Run), `reload.go` (table/uplink change handling), `adapters.go` (monitor → checker failures, status Source, monitor RouteOf by outbound tag), `admin_windows.go` / `admin_linux.go` / `admin_other.go`, `app_test.go`.

- `New` builds every child from the config through small interfaces the root defines (`procRunner`, `clashClient`, `checkerAPI`, …), so the wiring test can inject fakes.
- `Run`, in the contract's order:
  1. Pre-flight: admin check (→ exit 2 with the exact command to run elevated); `procman.CleanupStale("sing-box", "winws2", "nfqws2")`; `paths.Ensure`.
  2. Start the checker goroutine and take `checker.Table()` immediately (store or defaults).
  3. `netif.Uplink` → `desync.Build` → write `Files` to `Paths.Run` → start the engine with procman (skip it when the plan is empty). On Linux, check that the nft table exists; if it is missing, print `Setup` and exit 2 (G8).
  4. `singbox.Generate` → write `Paths.Run/sing-box.json` (atomically) → `singbox.Check` → start with procman; `Ready` = `clashapi.Version` succeeds.
  5. Start the monitor (sink → `checker.ReportFailure`) and the status server.
- Reload loop: listen on `checker.Subscribe()` and on `netif` uplink changes. Debounce (for example 3 s, from the clock). Regenerate both outputs and compare bytes with the files on disk; if they differ, write and restart/reload only the affected process. A failed `sing-box check` keeps the old file and process and logs an error. When the desync list becomes empty, stop the engine; when it stops being empty, start it.
- Connect/disconnect (ADR 0003, G16): two states inside `Run`.
  - *Disconnected*: the checker, the reload bookkeeping and the status/control server run; sing-box, the desync engine and the monitor are stopped.
  - *Connected*: steps 3–5 above. Disconnect stops the monitor, sing-box and the desync engine (in that order) and keeps the checker.
  - `splitter run` (terminal) connects at once, as today. `splitter run --ui` (started by the Tauri app) starts disconnected and waits for Connect over the API.
  - The App exposes `Connect(ctx)`, `Disconnect(ctx)` and `State()` to its own adapters (internal to `pc`, not a public API). The reload loop regenerates files in both states but only restarts processes while connected.
- UI parent watch (v1, G17): `--parent-pid <pid>` → when that process exits, shut down cleanly. An elevated `splitter` cannot be put into the UI's Job Object, so this is how it dies with the UI.
- Shutdown in reverse order: status, monitor, sing-box, desync, checker. Each step is bounded by a timeout. Errors are joined; the first runtime error → exit 3.

Tests (all fakes, fake clock): connect → disconnect → connect (processes stopped and started again, the checker untouched), `--ui` starts disconnected, a table change while disconnected restarts nothing, parent exit → clean shutdown, startup order, desync started before sing-box, an empty desync list means no engine, a table change that touches only desync domains restarts only the engine, a change that touches only the tunnel restarts only sing-box, a failed check keeps the old config, the debounce merges a burst, the reverse shutdown order, the needs-admin exit code, monitor failure → `checker.ReportFailure` mapping.

### M11 — smoke (manual / integration)

- `//go:build integration` test: generate + `sing-box check` with the pinned binary; winws/nfqws renderers checked with `--help` / `--dry-run` if the pinned build supports it.
- Windows smoke checklist (human, admin): `splitter run` brings up TUN + winws, the status page responds, killing `splitter` leaves no `sing-box.exe` / `winws.exe` (Job Object).
- Linux smoke checklist (human, root): print and apply the nft `Setup`, run, tear down with the printed `Teardown`.

### M12 — control API for the desktop UI

Needs: M10, and a decision on G15 (where the API lives). Contract first: write the endpoint list into the chosen module's `API.md` and get it approved before coding.

- Versioned JSON under `/api/v1/`, loopback only, same hardening as M8 (Host check, no CORS, timeouts).
- Token **required** (unlike the optional status token): `Authorization: Bearer <token>`, constant-time compare. Token handoff in v1 (G18): the UI writes a random token to a file in its own per-user directory and passes the file path as `--token-file`; `splitter` reads it once, keeps it in memory and never logs it. The UI picks the port, or passes `127.0.0.1:0` and reads the chosen port from a line `splitter` prints on stdout (decide in M12).
- Read: `GET /api/v1/state` (connected/disconnected/starting/stopping + the status `Snapshot`), `GET /api/v1/routes` (the current table), `GET /api/v1/processes`, `GET /api/v1/logs?name=` (procman ring buffers), `GET /api/v1/version`.
- Actions (POST, JSON body, idempotent where possible): `connect`, `disconnect`, `check-now` (optional domains → `checker.CheckNow`), `shutdown`. Later, after a separate decision: a per-domain route override and a list reload.
- Events: `GET /api/v1/events` as Server-Sent Events (stdlib only): state changes, table changes (`route.Diff`), procman events, a traffic tick every few seconds. No full hostnames unless debug is on, same rule as the monitor.
- Errors: JSON `{ "error": "...", "code": "..." }` with HTTP status codes; a missing/wrong token → 401 with no body detail.

Tests: `httptest` with a fake App: the token is required, actions call the right App methods, state transitions are visible on the event stream, a non-loopback listen address is rejected, no CORS headers, the SSE stream ends on shutdown. A golden JSON for each GET.

## 2. Decisions on the contract gaps

Decided 2026-10-01. The API changes are already recorded in the modules' `API.md`.

| # | Module | Gap | Decision |
|---|---|---|---|
| G1 | desync | `PortRange` was used but not defined | **Decided:** `type PortRange [2]uint16` (inclusive; same shape as the children's `[2]uint16`) |
| G2 | procman | `RestartPolicy` was not defined | **Decided:** `type RestartPolicy string`; `RestartOnFailure` (default, also for `""`), `RestartNever` |
| G3 | procman | Windows: children must die with the parent; the Job Object API is not in the stdlib | **Decided:** Job Object with `KILL_ON_JOB_CLOSE`, Win32 calls loaded from `kernel32.dll` via `syscall.NewLazyDLL`; no new dependency. The short gap between start and job assignment is accepted (our children do not fork early) |
| G4 | procman | Linux `Pdeathsig` fires when the *thread* that started the child exits, not the process | **Decided:** start every child from one goroutine pinned with `runtime.LockOSThread` that lives as long as the manager |
| G5 | singbox / monitor | `direct` and `desync` shared one outbound, so connections could not be told apart | **Decided:** separate `desync` outbound (also a direct outbound); `RouteOf` maps by the outbound tag |
| G6 | singbox | the final (default) route has no config field | **Open:** to be filled later |
| G7 | singbox / pc | where the Clash API secret comes from | **Decided:** internal; the app generates a random secret at each start, writes it only into the 0600 generated config and its own client; not configurable, never logged |
| G8 | pc / nfqws | what `run` does when the nftables rules were not applied | **Decided:** `run` checks read-only for the `inet splitter` table; if missing, it refuses to start, prints the `Setup` (and `Teardown`) commands and exits 2 |

Still to handle inside the milestones (no API change):

| # | Module | Item | Plan |
|---|---|---|---|
| G9 | pc | `LogConfig` is not defined | `Level`, `File` (under `Paths.Logs`), `MaxSizeMB`, `MaxFiles`; `log/slog` text handler, rotation by size (M9) |
| G10 | pc | an uplink change (Wi-Fi ↔ Ethernet) also changes the winws `IfIndex` / nfqws `oifname` | the reload loop also listens to `netif` uplink changes (M10) |
| G11 | pc | admin rights are detected only after a child fails | pre-flight check: Windows token elevation through a lazy DLL, Linux `euid == 0` or `CAP_NET_ADMIN` (M10) |
| G12 | singbox / pc | checker probes must not go through the TUN | the direct dialer binds to the uplink (`netif.BindControl`) *and* our process is in `OwnProcesses`; tested in M10 |
| G13 | desync / winws | unclear whether winws2/nfqws2 re-read the hostlist on change | verify with the pinned zapret; auto-reload → rewrite the file only, otherwise restart (M10) |
| G14 | singbox | Windows has no SIGHUP, so a sing-box reload is a restart that drops connections | debounce, restart only when the generated bytes differ, longer debounce for sing-box (M10) |

## 3. Not in this plan

- Strategy discovery for the desync engine (the "future strategy finder"); `Strategy` comes from config.
- Per-domain route overrides and list editing from the UI (after M12, separate decision).
- The Tauri app itself (its own tree, see ADR 0003 Open).
- Service installation (Windows service, systemd unit); v1 uses a UAC/pkexec prompt per connect (ADR 0003).
- The lab scenarios (`lab/*`); nfqws gets its real-packet test there.
- OpenWrt (`internal/router`).
